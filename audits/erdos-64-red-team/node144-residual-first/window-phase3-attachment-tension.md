# [144a] window history: select the actual attachment tension

The live object is the same selected graph `G` and one
`typeBHandoff` source-and-envelope witness from the literal window
history. For each assigned cubic first neighbour `a∈K_h`, the edge
`ha` leaves exactly two non-`h` incidences. The accepted account
places **every one** in the declared skeleton `F`, the extra
internal edge set `I=E(G[S])∖E(F)`, or the actual cut
`δ_G(S)`. The last category can be empty. Different assignment
indices can use one physical edge, and one exterior component can
receive several incidences. The core skeleton may be disconnected.

**Selected compatibility question.** Can the complete pattern of
these two incidences at each assigned neighbour coexist with the
retained high-centre normal form, bridgelessness of `G`, the
`FanSafe` relation on distinct assigned neighbours,
target avoidance, and the original minimality restrictions? More
concretely: after quotienting the actual exterior components only
for inspection, can all fan-neighbour incidences be contained or
reused without either (i) forcing an excluded local landing/return
pattern, (ii) yielding an admissible smaller replacement, or
(iii) paying an effective *physical* edge/component cost? The
question is about the handoff envelope itself; it does not require
assigning every source pair in `P` to that one envelope.

The three physical locations have different prospective effects.
An incidence in `F` may support a locally closed fan assignment;
an extra edge in `I` is a distinct physical chord or component
join; and an exterior edge enters a component with at least two
boundary edges in the actual bridgeless graph. The accepted
`β(F)` identity includes the component-merger correction, so
neither an `I` edge nor an outside component is automatically one
new rank unit. If two distinct assigned neighbours have a return
through an exterior component, `FanSafe` already excludes
accepted shifted return lengths and the instantiated
`WindowLabelCollision.LabelCollision` predicate; that
geometric exclusion by itself is **old**. A useful move must
derive a *new* restriction on which attachments or reuse patterns
can survive, or a legitimate account with bounded multiplicity.
Denials of exits (4)–(6), if invoked, need their separate retained
ledger facts and applicability; they are not fields of this
`FanSafe` proposition.
Same-neighbour returns and arms whose first edge is `ha` remain
explicit exceptions.

**Prospect and weakest case.** The strongest supported prospect is
a local attachment classification in which every outcome has one
of those three payoffs on the original `G`. The weakest case is
`D=D_F`: all non-`h` incidences are already represented in the
declared skeleton. Even there, the handoff does not provide the
certificate-marked fan support needed to import the paper's B1
charge. Therefore Phase 4 must test this case explicitly, not
declare it paid because its edges lie in `F`. The other weak
case is repeated use of one exterior component, where the
uncorrected `G-S` rank terms cannot be charged separately.

**Rival comparison.** The previous full-route Menger and terminal
count attempt inspected source paths. Its valid terminal bound had
no consumer from terminals to a bounded envelope charge; it did
not restrict the handoff envelope itself. The direct
source-pair-to-rank proposal also fails at the measured interface:
`M` is supported precisely on fan edges already in `R`, while
`P_0` may be nonempty. The actual fan-incidence/attachment
question is better supported for this residual because its two
incidences per assignment and its three physical locations are
exhaustive even when no original source route touches the fan.

**Selection.** Investigate that physical attachment pattern,
starting with the boundary of an actual `G-S` component reached
by an assigned cubic neighbour and retaining the all-in-`F`
case as a required sibling. No construction or cap is authorized
here. The next stage must catalogue a local mechanism for both
cases, including same-neighbour landings, component reuse, and
disconnected `F`; an outcome that merely restates
`FanSafe` or `selection` is not a payoff.
