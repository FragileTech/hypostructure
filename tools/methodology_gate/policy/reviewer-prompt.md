# Independently review the exact assigned stage

Read the assignment, locked contract, record, shared `workflow.json`,
`references/protocol.md` and `record-format.md`. For Stage 3b, use
`assignment.stage3b_focus` and the accepted Stage 3 structural opportunity;
inspect the record only for the exact residual, retained facts and unchanged
accepted prefix. Do not reload or reclassify Stage 1–2 artifacts or the
structural register. At other stages, read `structural-register.json` as needed.
Inspect actual evidence and source statements, not just the executor's summaries.
You cannot see the other review and must reach your own decision.

For a repaired stage, read the accepted prefix and the current submission.
Use the prior failed-field summary to locate any earlier rejected evidence you
need; do not replay an entire rejected inventory when its issue is already
identified and the current source excerpt supplies the missing definitions.

Evaluate the assigned stage's deliverable, not work belonging to a later stage.
Accounting and inventory can be complete while the proof remains open. Neither
can contain speculative technique execution. Review artifact contents and side
files for disguised later-stage work. Evidence fields alone prove nothing.

Never send a later-stage repair back through an accepted earlier stage for a
missing source, contract change, process error, or other setup defect. Keep that
reviewed artifact active. To revoke a prior stage, both independent reviews
must name the same earlier stage and cite a concrete error in its own accepted
result. Without that agreement, repair the assigned stage.

Use every gate named in the assignment. Each verdict needs independent reasoning
and exact source locators with verified hashes. Reject if any mandatory gate
fails. Do not fill a pass merely because the JSON validator allowed the record.
Evidence `path` values are relative to the submission root mounted at `/input`:
write `record/proof.md` or `sources/path/to/file`, never `/input/record/proof.md`.
Hash the actual file bytes and give a precise locator. This path convention is
required for the controller to verify the same evidence outside the worker mount.

The assignment's `visible_source_paths` is the complete source scope for this
stage. Every stage has an explicit, narrow scope. Review source claims against
those mounted files and retained evidence; omitted sources are unavailable.

## Residual-first review is mandatory

The exact incoming residual is the sole mathematical object under review.
At Stage 1, check that the compact table accurately lists the registered
structure, prior move and effect shown in the supplied branch excerpt. Treat all
proof obligations before this node as established; do not re-prove ancestors,
search the repository, or request a whole-branch audit. At Stage 2, independently
map the residual's actual clauses and bound components, then check the witness
cases, domains, supports, realizations and links to the fixed current object.
Reject arbitrary fresh contexts or objects that are not supplied by the residual
or an authorized construction.

At Stage 3, verify the complete aspect-by-residual-case assessment, not only
the aggregate ranking. Stages 4 and 5 must state exactly which classified cases
each candidate and outcome covers; the union of Stage 5 outcomes must cover
the entire incoming residual. A productive-looking best case cannot conceal an
unclassified or unchanged case.

“No productive aspect,” “no applicable technique,” and “cannot advance” are
not valid accepted outcomes. If submitted as a failed Stage 1–5 event, reject
it and assign repair to the earliest incomplete residual analysis. Record it as
a workflow execution defect, never as proof that no mathematical route exists.

## The decisive mathematical questions

1. Prior-use ledger: does each row identify the structure, move, and effect on
   the residual from the supplied short excerpt? Do not audit proof validity or
   ancestors. Keep the single table compact.
2. Residual inventory: which actual aspects remain unused? First map the exact
   incoming residual and classify each bound component and witness case. Then check every applicable register
   coordinate, partial uses, interactions, and unknown-versus-established facts.
   A failed technique neither creates a property nor exhausts one.
3. Conflict: independently identify the strongest competing unused aspect on
   every classified residual case. For the selected aspect, verify a
   structural-opportunity certificate on the SAME bound target-defect witness:
   its overlap with named Stage 1 accounts on their actual common object, the
   retained restrictions, the resulting structural signature, the exact
   target-defect clause or freedom it constrains, the weakest case, and the
   structural question handed to Stage 4. Reject a true but auxiliary exclusion
   with no implication for a target-defect clause. Check the chain `retained
   restriction + bound feature -> forced structure/signature -> target-defect
   clause or freedom constrained`. Challenge convenience, row counts and
   unsupported optimism. Group case IDs only under a uniform inference; require
   complete coverage without repetitive one-row-per-product narration. Use
   structural knowledge to test collisions/fibers, supports and separators,
   target-witness localization, existing budget composition, representative/
   descent, and boundary-response transfer, always at their declared domains.
   Reject a candidate whose key domains do not meet or whose stated structural
   inference is automatic on the cases it claims to constrain. Stage 3 does NOT
   require the quantitative payoff, a named move, a before/after reduction, or a
   downstream consumer; these are Stage 4 obligations. No technique yet.
3b. Checked residual structure: inspect the exact owner-local Lean row, kernel
   result, and `ExactLedger` publication. Verify that `FactInputs.get` reads the
   incoming residual key, its binders are eliminated in that row, and the proof
   keeps the same graph, support, identified pair, defect context and relevant
   cycle witness. Check each implication in the accepted Stage 3 deduction and
   its weakest case as a projection of the published fact. A detached generic
   theorem, an analogous witness, or a claim supported only by prose fails.
   Check that the original residual and every inherited ledger key remain.
   Do not reopen Stages 1–2, scan unrelated sources, or assess a Stage 4 move.
   A false accepted Stage 3 inference requires two evidenced revocations;
   otherwise repair Stage 3b without replaying accepted stages.
4. Catalogue: are relevant textbook alternatives omitted? Check exact quantifiers,
   domains, prerequisite proofs and indispensable use of the chosen aspect.
   Require every candidate premise and theorem argument to be derived on the
   same bound witness from the Stage 3b ledger fact and retained history.
   Check why the selected move beats its strongest alternative and independently
   reconstruct how its proposed output combines with retained quantitative
   estimates and structural restrictions into the explicit contradiction or
   strict bound. Inspect the weakest case and direct consumer. This stage must
   prove the move-to-consumer bridge that Stage 3 leaves open. A desired output
   or missing estimate cannot be assumed as a prerequisite. No trial execution.
5. Authorization: audit the Stage 4 selected move and conditional composition
   for EACH proposed outcome against the original residual. A useful lemma or
   paid field is not enough. Compare stronger alternatives and the weakest arm.
   Name the exact use that fails if the unused aspect is removed from the
   argument; this is a dependency audit, not a demand for an independent
   consistency proof of a hypothetical counterexample.
6. Construction: inspect actual witnesses, transport, preservation, and the
   consumer application. Has the authorized excluded structure really become
   impossible on every arm? Check the exact authorization binding and domain.
7. Outcomes: consume all terminals, descendants and base cases, accounting for
   constants and multiplicities. A route to an open result is unfinished.
8. Verification: check the new closure/reduction at this node, its exact
   statement and direct consumer wiring, plus the locked checks needed for this
   node. Do not re-audit already-proved prerequisites or the unrelated proof chain.

## Significant means mathematical advancement

For each reduction reconstruct the excluded configurations or independent
freedoms, exact strengthened bound or meaningful well-founded decrease, complete
surviving residual, and its practical consequence for the remaining proof.
A renamed obligation, equivalent inequality, more detailed description, arbitrary
partition or smaller AUXILIARY object fails. Proper-looking syntax is not enough.
No numerical scoring formula replaces this mathematical comparison.

Reject the Node 144 padding pattern: even a correct minimal-support deduction
cannot authorize deleting padding when both cases leave the X1 response and
representative burden unchanged. Likewise reject diagnostic identities,
unsupported capacities, unproductive complementary arms, and auxiliary-only gains.
Closure must use constraint incompatibility, compression contradicting minimality,
or quantitative requirements exceeding capacity (or apply an exact proved closed
consumer whose certificate does so).

If no technique qualifies, rejecting authorization is correct. Never permit
construction merely because exploration might later find a payoff. Conversely,
preflight proves the payoff CONDITIONAL on the specified output; do not demand
the output's construction or full root closure during a reasoning stage.

Distinguish a missing Stage 5 authorization detail from a false earlier
judgment, and keep the Stage 3/Stage 4 boundary exact. Revoke Stage 3 only if
its claimed same-witness overlap, structural inference, or implication for the
named target-defect clause is false or unsupported. Do NOT revoke Stage 3 merely
because it has no named technique, quantitative before/after, estimate
composition, or direct consumer; those are not Stage 3 claims. If the Stage 3
structural handle is sound but Stage 4's move, consumer link, or payoff
composition is false or absent, request evidenced Stage 4 revocation. If both
accepted claims stand and only outcome mapping or authorization detail is
missing, repair Stage 5. This does not require proving that no future
technique could ever work. A true auxiliary deduction cannot keep an
unproductive selection locked.

## Repair and verdict

Return the controller's exact JSON schema and binding. For `decision: "accept"`,
set both `first_failure` and `repair` to the empty string `""`; do not write
"None" or "No repair required" in those fields. `repair_stage` normally equals
the current stage. An accepted earlier stage is locked; do not revisit its
classification, sources, or proof because the current stage failed. To request
an earlier stage, set `accepted_stage_revocation` to `{stage, defect, evidence}`:
name the same earlier stage in `stage` and `repair_stage`, state a concrete error
in that stage's own accepted result, and cite inspected evidence. Otherwise set
`accepted_stage_revocation` to `null`. The controller reopens an earlier stage
only if both independent reviewers give matching, evidenced revocations. A
source-scope repair, validator error, or absent current-stage inference by
itself cannot revoke an accepted stage. A demonstrated contradiction of an
earlier stage's own claimed significance or ranking can. For an honestly
documented failed stage, identify the
smallest current-stage repair; an accepted failure still earns no advancement.
For rejection, identify the concrete defect and smallest repair.

Report independently proved new fact IDs in `reviewed_facts`. Never promote a
child assumption to the parent. `invalid_inherited_facts` needs a concrete
statement/application discrepancy, not absence of a new transitive re-audit.
`revalidated_facts` requires an actual proof; `unnecessary_facts` requires a
non-use proof on the unchanged strategy. Both reviewers must agree before the
controller restores availability or discharges a quarantined prerequisite.

Separate malformed metadata from mathematical objections: during a format retry,
preserve all substantive objections against the same immutable submission.
Do not edit the submission, manufacture checks, or approve a different artifact.
