# Residual-first structural reasoning protocol

On the complete current residual, identify an underused structural interaction, apply a suitable local move, integrate every outcome with retained facts, and continue on each exact survivor.

The task controller uses the contracts below for new runs. The older stage runner remains available for existing EG runs. Neither metadata path carries mathematical proof facts.

## Fresh context for every atomic task

One atomic mathematical problem per fresh context, in every phase including Phase 0, reviews and retries.

The controller launches a new ephemeral isolated worker for each assignment. Never resume, fork with conversation history, or reuse an earlier worker context.

Supply the complete pinned residual and applicable retained hypotheses, exact object identities, accepted evidence declared for this task, one goal, one output artifact, acceptance criteria and a first-failure rule. Carry proof state through these artifacts only.

The worker solves only the assigned inference, construction, comparison or check. A phase containing several obligations uses several fresh contexts. The branch endpoint and parent payoff are context, not additional worker goals.

Return one result and terminate. At the first missing inference, return NEEDS_DECOMPOSITION with immediate subobligations. Only the controller may assign a child or next task in another fresh context.

Two independent fresh reviewer contexts inspect the single result. Neither sees the other review. The controller alone accepts and integrates it before dispatching the next task.

Before construction, every outcome must have a proved productive conditional payoff on the complete residual and a reviewed Phase 5 admission. A successful build cannot supply missing admission evidence.

If fresh context or OS isolation is unavailable, stop the launch and report the execution failure. Never perform the proof in the controller conversation as a fallback.

## Phase 0. Restore the exact residual

Reconstruct the complete incoming state without hidden premises or guessed identifications; merged alternatives remain tagged.

Tasks: pin_source_revision, state_endpoint, identify_incoming_alternative, register_retained_object, check_inherited_premise, record_minimality_or_import.

## Phase 1. Account for used structure

Input: Exact Phase 0 branch snapshot.

Output: Per-object, per-use structural ledger, including resource balances and unresolved interactions.

Gate: Every claimed earlier use has a cited result; reusable premises and finite resources are distinguished.

Atomic tasks: record_prior_use, state_prior_result, identify_unused_interaction, check_account_balance, check_transport.

## Phase 2. Inventory unused structure

Input: Exact residual and prior-use ledger.

Output: Actual observables and unresolved interactions, including higher-order conjunctions; no technique selection.

Gate: Each candidate is anchored in the retained object and unknown properties remain unknown.

Atomic tasks: inspect_coordinate, name_observable, register_interaction, compare_attempt, state_unresolved_question.

## Phase 3. Select a structural tension

Input: Unresolved interactions on the full residual.

Output: One compatibility question, supported prospective payoff, serious rival comparison, and selected local aspect.

Gate: The selection identifies an actual structural relation before choosing a method.

Atomic tasks: relate_restrictions, state_prospective_consequence, justify_prospect, compare_rival, select_tension.

## Phase 4. Catalogue textbook moves

Input: One selected structural tension.

Output: Exact local mechanisms, prerequisites, complete outcomes, and attempt fingerprints.

Gate: Missing prerequisites and exceptional cases remain explicit; no construction yet.

Atomic tasks: state_textbook_move, match_prerequisite, specify_output, state_proposed_effect, compare_attempt_fingerprint, select_candidate.

## Phase 5. Prove local payoffs and authorize

Input: One candidate move with its outcomes.

Output: For each outcome, an accepted conditional implication from the full branch to closure or a precise productive restriction.

Gate: Every outcome has reviewed payoff evidence; prerequisite submoves finish before dependent construction.

Atomic tasks: define_outcome_payoff, prove_conditional_inference, specify_survivor_analysis, check_prerequisite, reject_cosmetic_payoff, decompose_construction, review_admission.

## Phase 6. Execute one construction task

Input: Pinned branch and authorized ready obligation.

Output: One actual construction, inference, preservation, account update, or coverage proof on the retained objects.

Gate: Evidence is tied to the actual witnesses and no missing inference is hidden.

Atomic tasks: define_object, prove_property, prove_identification, preserve_condition, update_account, establish_alternative, check_coverage, review_inference.

## Phase 7. Integrate and continue survivors

Input: Accepted new results plus all retained facts and accounts.

Output: Integrated consequences, separate constraint/compression/quantity tests, exact survivors, and next local obligations.

Gate: Every outcome closes with evidence or remains an explicit open residual; move credit also requires real payoff on every arm.

Atomic tasks: relate_new_and_retained, prove_integrated_consequence, reconcile_account, revisit_blocked_move, review_integration, test_constraint, test_compression, test_quantity, form_survivor, record_advancement, prove_refinement, prove_coverage, prove_recursive_decrease, name_next_obligation.

## Phase 8. Verify and synchronize

Input: Accepted local work and every remaining branch obligation.

Output: Exact endpoint proof or honest reduction theorem with synchronized formal and manuscript views.

Gate: Closure is derived from complete AND-case coverage, current evidence, and the required implementation checks.

Atomic tasks: review_terminal_implication, check_transition, check_handoff, check_recursive_field, check_formal_implementation, check_composition, synchronize_views.

## Three completion units

**task:** One construction, inference, comparison, or check is complete when its exact output has accepted evidence.

**move:** A structural move is productive only when every outcome closes or has a reviewed significant structural payoff on the exact residual.

**branch:** A branch closes only when every reachable outcome is discharged and the exact endpoint follows by accepted composition.

## Existing stage runner contracts

An accepted stage is locked: never execute, reconstruct, reclassify, or re-review it during a later-stage repair. Carry its exact reviewed artifact forward. A later failure, missing source, changed source scope, validator error, or missing productive conflict cannot unlock it. Default repair_stage is the stage that failed. Only two independent reviewers may formally revoke acceptance by naming the same earlier stage and citing concrete evidence of a defect in that stage's own result; only then may repair move backward. A failed Stage 6 construction returns to Stage 5 authorization under the construction-failure rule.

Preflight proves the conditional payoff; execution constructs the output and proves actual advancement. No useful auxiliary lemma or paid interface field alone completes a productive step.

## 1. List the structure and moves already used

Input: The exact retained incoming residual and a short source excerpt for this already-proved branch.

Required result: One compact table listing each previously exploited registered structure, the move that used it, and its effect on the incoming residual.

Review: Check only that the listed structure, move and residual effect match the supplied branch excerpt. Trust all proof obligations before this node as established. Do not re-prove ancestors, reconstruct the residual, search the repository, or scan unrelated sources. Keep this ledger to a few pages; it is the single prior-use template for later stages.

Gates: compact_prior_use_ledger, registered_structure_ids, move_to_residual_effect.

## 2. Decompose and classify the incoming residual

Input: The exact residual and Stage 1's compact prior-use ledger.

Required result: An exact component map of the residual, plus an exhaustive classification of each bound witness in relation to the fixed current object. No techniques.

Review: Work only from the exact residual and sources explicitly scoped for this stage. Classify each actual residual-bound witness and explain the cases relevant to it. Do not inspect or re-prove upstream proof steps, introduce arbitrary objects, or treat unknown structure as a premise.

Gates: residual_component_decomposition, register_coverage, unused_aspect_novelty, residual_case_exhaustion, structural_interactions, no_technique_selection.

## 3. Select the strongest residual-grounded conflict

Input: Every classified residual case, established unused aspect and accumulated restriction.

Required result: A ranked comparison covering every residual case. The selected structure must have a same-witness structural-opportunity certificate: identify the actual target-defect witness; show its overlap with named Stage 1 accounts on their common object; derive the structural signature forced by the retained restriction and residual feature; name the exact target-defect clause or freedom this signature constrains; state the concrete Stage 4 exploitation question and weakest case. This establishes target-relevant structure, not the technique's quantitative payoff or final consumer. No technique selection.

Review: Analyze the exact bound target-defect witness throughout. For each candidate, name its relation to a Stage 1 account on the same actual object and derive a structural consequence on a clause or freedom of that target defect. Group Stage 2 cases only under a uniform inference, with complete case-ID coverage and no repetitive product table. Identify the weakest case and what remains open there for Stage 4. Do not require a named move, a quantitative before/after, a final contradiction, or a direct consumer in Stage 3; those are Stage 4 obligations. Do reject an auxiliary fact, unrelated support exclusion, or marginal case deletion that has no proved implication for any target-defect clause. Do not reject a genuine residual-specific structural handle merely because its link to a downstream response field, estimate, or consumer has not yet been derived. Compare the strongest structural alternatives without choosing a technique. A missing target-relevant structural handle is an execution defect to repair, never a valid endpoint.

Gates: exact_bound_witness, adversarial_structural_reasoning, prior_account_overlap, same_witness_structural_overlap, target_residual_handle, grouped_residual_case_coverage, weakest_case_handoff, strongest_alternative_comparison, maximal_structural_restriction, no_technique_selection.

## 3b. Prove and publish the selected structure on the incoming residual

Input: Only the node's exact incoming residual, the selected Stage 3 structural opportunity on its bound witness, and the existing ExactLedger keys needed to derive that structure. Accepted Stages 1–2 are locked context, not tasks to repeat or reclassify.

Required result: Eliminate the incoming residual's actual bound tuple inside one owner-local Lean row. Prove every selected Stage 3 structural implication, including its weakest case, on that same tuple and publish exactly one checked fact under a new key in the canonical ExactLedger. Retain the residual key and all inherited keys. Give each implication an exact projection of the published fact. No generic replacement theorem, new arbitrary witness, move selection, or reduction claim.

Review: Reject any proof that switches the graph, support, pair, context, cycle witness, or witness domain from the selected incoming residual. Inspect the owner-local row: it must read the incoming residual key through FactInputs, derive the selected structure there, and append only its proved fact through the canonical ExactLedger. Check every selected implication and the weakest case against the exact Lean statement, not commentary or an analogous generic theorem. Check the locked kernel result and preservation of the full incoming ledger. Do not reread or reclassify accepted Stages 1–2, enumerate unrelated declarations, audit the source tree, or perform Stage 4 technique work. Repair Stage 3b if its Lean derivation is incomplete; only a concrete false Stage 3 claim can justify formal Stage 3 revocation.

Gates: exact_residual_witness_binding, stage3_claim_realization, selected_claim_projection_coverage, inline_residual_to_ledger_derivation, lean_kernel_certificate, exact_ledger_publication, incoming_history_preserved, weakest_case_structure.

## 4. Catalogue residual-case techniques

Input: The accepted residual-case conflict and the Stage 3b Lean-checked structural fact in the canonical ExactLedger.

Required result: A complete technique catalogue and one selected best move applied to the incoming residual through the Stage 3b fact. For that move, give its exact output and a conditional derivation showing how it consumes the published structure and combines with retained restrictions and quantitative estimates into an explicit contradiction or strict bound on the same residual. Cover the weakest case, before/after residual, significance and direct consumer. No execution.

Review: Review all registered families attached to the selected aspect and other relevant textbook moves. Compare the strongest applicable alternative. Every admitted move must bind its theorem arguments to the same residual witness carried by the Stage 3b ledger fact, derive each prerequisite from that fact and retained history, and show algebraically or structurally how its exact output compounds into the advertised payoff. An unrelated context, support, token, or load is ineligible. Stage 4 owns the move-to-consumer and quantitative bridge. Do not defer discovery of usefulness to Stage 5 or construction.

Gates: technique_coverage, residual_case_technique_map, exact_textbook_hypotheses, indispensable_structural_dependency, best_move_selected, prior_estimate_composition, explicit_conditional_payoff, weakest_case_consumer, attempt_history_comparison.

## 5. Authorize a productive technique

Input: The accepted residual-case conflict and complete technique catalogue with its selected move and conditional payoff composition.

Required result: One exact construction authorization, bound to every classified residual case, with a proved closure or significant restriction on every case and every outcome.

Review: Audit the Stage 4 selected move and its already displayed conditional payoff against every classified residual case and outcome; state exact before/after, significance and the full survivor. Stage 5 may refine authorization details, but must not first discover whether the approach affects the residual. Request Stage 3 revocation only if its claimed same-witness overlap or target-clause structural inference is false. If that structural handle is sound but the Stage 4 move, consumer link, or quantitative composition fails, request Stage 4 revocation. A missing current-stage authorization detail alone is repaired at Stage 5. No failed route is completion or proof impossibility.

Gates: conditional_payoff_proved, residual_case_payoff_coverage, indispensable_structural_dependency, strongest_technique_comparison, every_outcome_productive, significant_residual_reduction, no_cosmetic_retry.

## 6. Execute the authorized construction

Input: The exact independently approved construction and conditional payoff, bound to classified residual cases.

Required result: Actual witnesses tied to the retained residual, preserved interfaces, and a proved closure or significant residual reduction on every authorized case and outcome. Partial lemmas remain intermediate work.

Review: Check the indispensable use of the approved structure on the exact residual-bound object and actual application, not just the lemma’s correctness. Failed attempts earn no progress and invalidate authorization pending repair.

Gates: authorization_binding, actual_witnesses, transport_and_preservation, actual_proof_advancement, every_outcome_productive, positive_prefix_and_failure.

## 7. Consume all outcomes

Input: The proved construction, every classified residual case, every outcome and all reduced residuals.

Required result: Every terminal, classified case and descendant discharged, with exact account updates and no hidden remaining obligation.

Review: Routing and bookkeeping do not close a case. Preserve every complementary arm, all independent slack, exact multiplicities and the full surviving residual.

Gates: every_terminal_consumed, descendants_and_base_cases, multiplicity_and_strict_constants, updated_structural_accounts.

## 8. Verify closure of this node

Input: The completed closure or significant reduction of this node and the exact changed declaration/consumer.

Required result: The target node is closed or its residual is significantly reduced, with its changed declaration and direct consumer checked.

Review: Check the new result at the exact node statement and its direct wiring. Treat already-proved incoming prerequisites as fixed checked inputs; do not re-audit the earlier proof branch or unrelated dependency chain. Run only the locked checks needed for this node. Verification cannot introduce a new construction or change checked source replacements.

Gates: mathematical_proof, formal_statement, schema_and_wiring, direct_consumer_fidelity, kernel_and_finite_checks, target_node_closure.

## Shared requirements

Stage 1 is one compact prior-use table: registered structure, the move that used it and its effect on this residual. Trust proof obligations before the requested node; do not re-prove ancestors, reconstruct the residual in Stage 1, or scan unrelated sources. Stage 2 maps and classifies the exact incoming residual and its bound witnesses. Every stage contract names a nonempty source scope; there is no full-tree fallback. The residual remains the sole mathematical object. A register never substitutes for residual-case analysis, and no arbitrary mathematical object may be introduced without an authorized construction. “No productive aspect/technique” is an execution defect, not an accepted outcome or proof conclusion; repair the earliest incomplete residual analysis. The final check concerns the new result at this node and its direct consumer, not already-proved ancestors. Read executor-prompt.md, reviewer-prompt.md and record-format.md for the exact artifact fields. A failed technique does not exhaust a property.
